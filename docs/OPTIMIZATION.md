# 产品深度分析（纯产品视角 v2）

> 审查日期：2026-11-20 · 范围：仅插件产品本身（功能/链路/交互/架构），不含任何运营与获客内容
> 方法：对照「一个完美的 DSH 会话归档管理器」应有的形态，逐链路找差距；每个缺口标注现状/影响/方案/工作量

## 一、总体判断

核心删除链路（软删除/永久删除/级联子代理/回收站还原）已经**完整且健壮**，安全设计（CSRF 头/id 白名单/路径转义/审计）达到生产水准。真正的差距集中在四类：
**① 上次重构砍掉的能力没有补回 ② 家族会话（父子）处理不完整 ③ 长期运行细节（轮转/持久化/清理）④ 大数据量与多语言的产品化短板。**

## 二、功能完整性矩阵（✅ 已有 / ⚠️ 缺口）

### 1. 删除链路
| 能力 | 状态 |
|---|---|
| 单条软删除（回收站可还原） | ✅ |
| 单条永久删除（级联全部子代理） | ✅ |
| 运行中会话保护（409） | ✅ |
| 审计日志 | ✅ |
| ⚠️ 缺口 1：**批量管理未归档会话的入口缺失** | 原「全部会话」页签在 zcodex 化重构中移除；侧栏永久删除只能单条操作，几百个会话的批量清理没有界面入口。影响：重度用户的核心场景。方案：设置页恢复「全部会话」分组清单（可放页面底部次级入口），或侧栏加多选。工作量：中 |
| ⚠️ 缺口 2：**无「强制结束并删除」选项** | 对运行中会话只会 409 拒绝；竞品宣称 full agent teardown。DSH 未公开 agent dispose API，需评估宿主能力（terminals.kill 只管终端）。方案：文档说明 + 未来跟进宿主公开 API。工作量：中（依赖宿主） |

### 2. 归档链路
| 能力 | 状态 |
|---|---|
| 手动归档 / 自动归档（保留期可调） | ✅ |
| 置顶与运行中会话豁免 | ✅ |
| ⚠️ 缺口 3：**项目级豁免名单** | 某些项目（如长期挂着的参考库）不该被自动归档，现在只能靠置顶逐个保护。方案：配置加「豁免项目/路径」列表，扫描时跳过。工作量：小 |
| ⚠️ 缺口 4：**自动归档结果不可见** | 后台静默归档后用户无感知，只有进设置页才看到汇总。方案：扫描完成时客户端 Toast（数量+入口链接）。工作量：小 |

### 3. 还原链路
| 能力 | 状态 |
|---|---|
| 单条还原（原位归位 + 自动解除归档） | ✅ |
| ⚠️ 缺口 5：**家族还原不完整** | 删除父会话时子代理跟随进回收站（✅ 本轮已做），但还原父会话时子代理仍留在回收站——家族分离。方案：还原时检测同批子代理条目，弹窗勾选「一并还原」。工作量：中 |
| ⚠️ 缺口 6：回收站无「全部还原」 | 多条逐点太累。方案：底部加「全部还原」按钮（复用批量还原管线）。工作量：小 |

### 4. 回收站链路
| 能力 | 状态 |
|---|---|
| 软删除入回收站 / 单条与批量还原 / 彻底删除 / 清空 | ✅ |
| ⚠️ 缺口 7：**回收站无限堆积** | 没有过期清理，一年后回收站本身变成磁盘负担。方案：配置加「回收站保留 N 天自动彻底删除」（审计留痕）。工作量：中 |
| ⚠️ 缺口 8：**回收站无搜索/分组** | 条目多了找不到目标。方案：复用归档页的搜索与分组逻辑。工作量：小 |

### 5. 可信与合规
| 能力 | 状态 |
|---|---|
| 审计日志 / CSRF 头 / id 白名单 / 路径转义 / debug 鉴权（本轮修复） | ✅ |
| ⚠️ 缺口 9：**审计日志无限增长** | 永久追加无轮转。方案：超过 5MB 自动轮转为 audit.log.1。工作量：小 |
| ⚠️ 缺口 10：**卸载残留无说明** | 卸载插件后 config/audit/trash 留在磁盘。方案：README 增加「数据与卸载」章节说明位置与清理方式。工作量：小 |
