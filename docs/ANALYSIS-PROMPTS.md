# 产品深度分析提示词套件（ANALYSIS SUITE v1.0）

> 九个视角、一轮对抗、一份裁决。为 dsh-archive-management 定制，可整体迁移到任何产品。
> 设计目标：让任何 AI（包括最谄媚的）都**无法**输出表面功夫。

---

## 铁律（每条提示词内建，违反即分析失败）

1. **配额强制**：每条发现类提示词必须产出 ≥10 条发现，其中 ≥3 条必须是 P0/P1 级。凑不满就说明你没挖深，继续挖。
2. **证据强制**：每条发现必须引用证据——代码行号、页面元素、数据数值。没有证据的发现是想象，不算数。
3. **禁用词黑名单**：输出中禁止出现：「建议优化用户体验」「提升整体性能」「增加用户引导」「进一步完善」「有待提高」。出现一次，重写全部。
4. **自我对抗**：产出后，以「最讨厌这个产品的竞品开发者」身份攻击自己的每一条结论，攻击成功的结论作废。
5. **不许夸**：优点最多占输出的 10%。这不是表彰会。

## A4 失败模式与边界分析（FMEA）

```text
你是安全工程师，执行 FMEA（失效模式与影响分析）。假设代码是 guilty until proven innocent。

系统：删除/还原/级联/自动归档/审计 五条管线，运行于 Windows/macOS/Linux，
数据位于 ~/.dsh/（sessions / trash / storages / audit.log / config.json）。

对以下每个操作，穷举失效模式：
软删除（含级联）→ 永久删除（含级联）→ 还原 → purge-archived → 自动归档扫描 → 配置读写 → 审计追加

维度：并发（双窗口/多客户端）、磁盘（满/只读/路径超长/Unicode 路径）、
权限（只读目录/文件被占用/杀毒软件锁定）、时序（扫描与手动操作并发、
还原与删除竞态）、数据（id 异常字符/超长标题/meta.json 损坏）、
权限边界（回收站条目被外部工具改动）。

输出 FMEA 表：失效模式 | 触发条件 | 当前代码行为（引用函数）| 后果严重度(1-10) |
发生概率(1-10) | 检测难度(1-10) | RPN 排序 | 建议防御。
RPN ≥ 100 的条目必须给出具体修复代码方向。总数 ≥15 行。
```
