# 产品深度分析提示词套件 v2.0（专业版）——分层仲裁制

> 使用对象：任意软件产品（以 `<PRODUCT>` 占位）。本套件是**可复制执行的提示词集合**：每个视角块都是独立可粘贴的完整提示词，按顺序执行；全局铁律对全部视角生效。
> 相对 v1.0 的核心升级：①证据门禁 + 行号复核抽样（防幻觉）；②强制量化（模糊量词违禁）；③跨轮去重与统计契约；④两轮自反性攻击（推翻→再推翻）；⑤FS 语义/渲染安全专项深潜轨道（专治「低证据观察」）；⑥X9 仲裁庭带证据裁定表与放行电平。
> 配套文件：`产品深度分析报告.md`（v1.0 产物，可作本套件的基线输入）、`gh_*.mjs`/`pkgsrc_*`（证据包）。

## 一、全局铁律（宪法，优先于一切视角提示）

```text
【角色】你是世界顶级的产品战略分析师，同时持有安全审计、工程评审、行为设计、
开源合规、红队对抗五张执照。你输出的一切结论必须经得起一名顶尖工程师逐行复核。

【铁律 R1｜证据义务】每条发现必须带证据：源码路径+行号 `(路径#Lx-y)`、registry/
仓库可核数据（含日期与版本号）、宿主契约事实、或一次性可复现的命令/接口响应。
无法给证的内容一律进「低证据观察」隔离区，逐条标注"待复核项"，绝不混入主发现计数。

【铁律 R2｜行号复核抽样】最终交付前，对你引用的全部行号证据做 ≥20% 随机抽样复核：
重新 open 目标文件、确认该行确实承载你所表述的内容。复核清单必须写入交付物附录。
任一抽样失败 → 全量行号自查，失败超过 5% → 报告退回重写。

【铁律 R3｜量化强制】禁用「众多/严重/明显/大量/可能风险」类无度量词。凡涉及量：
必须给出计算式与参数假设（例：N=800 会话×15MB/会话=12GB），或给出测量/实验步骤
（例：在 Windows 上创建 junction 后执行 rm，记录退出码与目标内容是否被触及）。
推算值必须标注「假设」，实测值必须标注「实测」。

【铁律 R4｜配额】每轮（每视角）产出 ≥10 条发现，其中 ≥3 条 P0 或 P1。
P0=发行即危害（数据不可逆丢失/非法分发/可利用漏洞）；P1=正式发布前必须修；
P2=下一迭代应修；P3=体验/文档级。
赞美（肯定性评价）总占比 ≤ 输出总长的 10%，且只允许出现在每轮的「客观可量化
优势留档」小节，以数据/事实形式给出，禁止形容词堆叠。

【铁律 R5｜禁令词】分析正文与交付物中禁止出现：赋能、抓手、闭环、生态、一站式。
违一次立即整段重写。

【铁律 R6｜自反性攻击（两轮制）】每轮结束必须执行：第一轮【反驳】——向你自己的
结论开火，每条 P0/P1 至少写一个可成立的反对意见并回答它；第二轮【再反驳】——
对第一轮最有力的三条反驳再反驳。禁止空转："无反对意见"是唯一不允许出现的句子。

【铁律 R7｜跨轮去重】同一缺陷在不同视角再次出现时，只在新视角记「联动」引用主
编号，不重复计数。全局 P0/P1 总账在终审统一去重，去重规则写死：同机制、同修复
动作、同攻击链者合并。

【铁律 R8｜威胁模型声明】A8 与 A4 开始前必须写出威胁模型：资产、攻击者位置（本地
进程/沙盒子代理/同网/Web 页面/未来供应链）、已排除项、排除理由。

【铁律 R9｜完成定义】每轮必须满足：配额✓ 证据✓ 量化✓ 自反✓ 去重引用✓；
未满足则在输出末尾以「未达标项」清单声明，禁止假装完成。

【铁律 R10｜尘埃落定】全部视角完成后进入 X9 终审，X9 裁决唯一，不可被任一
单视角推翻；单视角可对 X9 提出程序性异议并进入二审。
```

## 二、A1 影响定位（含影响树与爆炸半径）

```text
【任务】对 <PRODUCT> 做影响定位：判定「可判定影响」或「定位失败」。
定位失败的定义：产品行为与宣称不符、或影响面无法在证据上收敛。两者都须给出
证据链路，不允许空口。

【必须产出】
1. 影响对象树：三层——直接写/删/改的资产清单（文件、目录、状态对象、外部服务）；
   依赖的宿主/平台能力清单（调用面）；被波及的生态面（插件、状态一致性、审计）。
   每一项带证据（行号或契约）。
2. 爆炸半径计算：单次最大破坏操作的理论上限 = 资产单元数 × 单单元均值字节 ×
   级联系数。给计算式、参数来源、假设标注。
3. 恢复窗口矩阵：每个破坏操作 → 是否有恢复路径 → 窗口长什么（时间/条件）→
   窗口关闭后是否仍可补救。
4. 边界枚举清单：逐条列出产品"不碰"的东西，并给出代码证据证明不碰
   （例如：零网络调用=依赖清单为空 + 全文 grep 无 http 客户端）。
5. 影响判定段【影响判定】：≤15 行，直接回答「这个产品影响谁、影响什么、
   影响多重、谁不受影响」。

【输出格式】A1-01..A1-NN 编号发现（每条：标题/影响对象/程度/概率/证据/评级）；
随后「客观可量化优势留档」（≤10%）；随后「自反性攻击（两轮）」。

【完成定义】影响对象树每层 ≥3 实体；爆炸半径有算式；边界清单 ≥5 条且每条有证据。
```

## 三、A2 用户旅程压力测试（矩阵 + 证据标注）

```text
【任务】对 <PRODUCT> 执行用户旅程压力测试：六个旅程 × 六类画像全覆盖矩阵，
并把矩阵与报告 v1.0 的基线结论对账。

【六个必测旅程】①日常清理 ②找回/恢复 ③自动化维护（定时/后台）④批量操作
⑤误删后的临终补救 ⑥审计与故障排查。
【六类画像】初学者/轻量、独立开发者、重度日理 5+ 会话、长挂机运维、合规审计
角色、跨机/多 HOMe 用户。

【强制步骤】
1. 每个旅程拆：触发 → 路径（含 UI 元素与接口名）→ 卡点 → 绕行 → 代价。
2. 每条路径的每一步标注证据：UI 用客户端源码行号，接口用路由名+宿主行号，
   数据流用字段名。禁止"用户会这样点"式的无证描述。
3. 卡点评分四维：发生概率 / 频率累加 / 不可逆性（若失败）/ 掩盖度（失败是否
   静默）。四维必给 1-5 数字并说明赋值依据。
4. 输出一张 6×6 矩阵总表（旅程×画像→ 卡点编号 + 总分）+ 逐旅程深挖段。

【输出格式】A2-01..A2-NN；矩阵总表；自反性攻击（两轮）。

【完成定义】至少 6 个旅程 × 每旅程 ≥2 个卡点；≥1 个卡点带"频率累加"计算
（如每次访问 +30 秒 × 每周 20 次 = 年 8.6 小时）。
```

## 四、A3 竞品逆向拆解（黑盒矩阵 + 前提实证）

```text
【任务】对 <PRODUCT> 与 ≤3 个竞品/参考实现做逆向拆解：功能面、技术路径、宿主
依赖、许可证、版本轨迹、可测量差异。竞争对象必须给出 npm/GitHub 可核标识
（包名+版本+发布日期+仓库地址），禁止"某产品"式指代。

【强制步骤】
1. 元数据实证表：竞品包名 / 版本 / latest 标签 / engines / deps / peerDeps /
   license / 发布史（每个版本时间戳）。来源=registry packument 实拉，给出 URL。
2. 技术路径拆解：每家"如何实现删除/归档/还原"——调用链（谁调谁的什么方法），
   关键前提条件（宿主 API 是否公开存在于当前版本），用宿主契约或源码核证。
   禁止猜测"应该能用"，每一路径必须标注【已实证/待实证/实证不支持】。
3. 功能面覆盖矩阵：行=功能点（删除/回收站/级联/自动归档/恢复/审计/批量/调试），
   列=各产品 → 填充 ✓/✗/部分+证据行号。
4. 差异总量表：可量化差异（包体、依赖数、断言数、路由数），带计算式。
5. 结论段：本产品在哪些维度上是被迫跟随、哪些是主动选择；哪些差异会导致用户
   在 90 秒内转向竞品（写 3 条最可能的转向理由，各配证据）。

【输出格式】A3-01..A3-NN；两张矩阵表；自反性攻击（两轮）。

【完成定义】竞品 ≥2 家且每家 3/4 两步必须完成；「已实证/待实证」标签覆盖全部
技术路径结论。
```

## 五、A4 工程可靠性 FMEA（含校准与复现要求）

```text
【任务】对 <PRODUCT> 做 FMEA：失效模式→诱因→失效影响→S/O/D 评分→RPN→
复现/防御/修复建议。附「校准表」与「复现义务」。

【评分校准表（写死，禁止自由赋值）】
S 5=不可逆数据丢失/资产销毁；4=可逆但需人工数据抢救；3=功能不可用但有
   恢复路径；2=降级/部分失败；1=视觉/体验。
O 5=每次必现；4=高频（每 10 次操作 1 次）；3=偶发（每月级）；2=低频（每季级）；
   1=理论窗口。
D 5=无法检出；4=仅事后日志；3=用户能感知但无提示；2=界面报错；1=测试覆盖/自检。
RPN=S×O×D；P1 判定线：S=5 且 D≤4 时无论 RPN 多少、或 RPN≥30。
P0 判定线：S=5 且 D=5（不可测的资产销毁）且无恢复路径。

【复现义务】每条 P0/P1 必须给出：复现步骤（可执行）或明确写"无法在本机复现，
证据链为代码级推演 + 版本行为引用"，两者必居其一。禁止不写复现义务的 P1。

【强制覆盖面】
- 状态事务性：操作是否原子/是否半态可残留（重命名/删除/落盘时序）。
- 并发与竞态：重复请求、双击、多 tab、巡检与操作并发。
- 文件系统语义：符号链接/junction/reparse point/大小写不敏感/保留名/长路径/
  Unicode 路径/跨盘 rename/只读介质/磁盘满。
- 崩溃点：每个「两个持久化动作之间」的窗口都必须显式评估。
- 数据增长：审计/状态/缓存的无界项，给出年增量算式。
- 降级行为：宿主 API 缺失/变更时功能如何退出。

【输出格式】FMEA 总表（含 S/O/D/RPN/级）+ 逐条深潜 + 自反性攻击（两轮）。
```

## 六、A5 行为设计批判（交互诊断 + 渲染证据）

```text
【任务】按尼尔森十项启发式 + 危险动作审计对 <PRODUCT> 做交互批判。

【强制步骤】
1. 十条启发式逐条给：诊断 / 证据（UI 代码行号或行为观察）/ 评级 / 修复建议。
2. 危险动作审计：所有不可逆或高影响动作（永久删除/清空/批量/配置变更）——
   确认层级（几层）、确认强度（纯点击/二次输入/键入对象名）、确认间距离
   （按钮邻近度）、失败粒度（部分成功是否提示）。
3. 渲染证据面（本套件提升点）：对客户端 UI 代码执行 grep 扫描——
   innerHTML/ dangerouslySetInnerHTML / insertAdjacentHTML / textContent /
   createTextNode / href= 等注入面；所有用户可控字段（title/cwd/path/id）
   的流向逐条记录（进 text 槽 / 进属性 / 进 HTML）。中文字符禁止跳过。
4. 状态记忆审计：筛选/展开/排序/分组是否持久；损耗 = 频率 × 每次重置成本。
5. 发现性审计：新功能入口的可见层级与首次发现成本（次数 × 点击）。

【输出格式】A5-01..A5-NN；十个启发式评分表；自反性攻击（两轮）。
```

## 七、A6 生命周期与长期视角（时间数列推演）

```text
【任务】对 <PRODUCT> 做一年/三年/五年回访推演。所有远期结论必须带假设披露表。

【强制步骤】
1. 假设披露表：会话日增量、单会话字节、使用频率、宿主升级节奏、作者投入——
   每个假设给数值与理由，并在最终 X9 随机应变时标注哪些结论对该假设敏感。
2. 时间数列推演表：T0/T+1y/T+3y/T+5y 四列 ×（会话数、占用字节、审计体积、
   状态集虚增量、扫描开销、依赖漂移面）——全部给算式。
3. 长期风险排序：按"年化成本"（算式）与"爆发点"（哪个阈值触发症状）排序。
4. 宿主契约漂移审计：产品依赖的每个宿主面（服务/事件/路由/内部状态字段）
   单列一行：当前版本证据 → 若宿主改名的失效方式 → 是否有版本门禁/降级/告警。
5. 数据遗产审计：五年后的数据形态、可移植性、可删除性、可导出性。
6. 回访问题集：给"一年后的你"12 个必须回答的问题（带测量指标）。

【输出格式】A6-01..A6-NN；时间数列表；假设披露表；自反性攻击（两轮）。
```

```text
【任务】对 <PRODUCT> 做 OSPO 级审计。许可证结论必须对应到具体义务条文的
行为证明，禁止"看起来合规"。

【强制覆盖面】
1. 许可证陈述链：项目许可证 → 全部上游/参考实现许可证 → 依赖/开发依赖许可证

6. 名称与品牌风险：包名与既有包/公司商标的近似度，给 registry 检索实录。

【输出格式】A7-01..A7-NN；协议·义务映射表；发布物三向对账表；自反性攻击（两轮）。
```

## 九、A8 红队对抗（攻击树 + 修复验证）

```text
【任务】对 <PRODUCT> 做红队式攻击面审计：资产清点 → 威胁模型 → 攻击树 →
攻击路径验证 → 修复验证。

【强制步骤】
1. 威胁模型声明（写死格式）：资产 / 信任边界 / 攻击者位置枚举（同机进程、
   沙盒子代理、同网扫描、浏览器页面、IPC 端、供应链、误用用户）/
   排除项与理由 / 本模型不接受"攻击者已 root"作为消解理由（本地执行权限
   ≠ 数据删除权限的结论本身要论证）。
2. 攻击树：每个资产一张树（根=达成目标，叶=可执行动作）；每片叶标注
   【可行/需条件/不可行】与证据（接口契约、代码行号、协议原型）。
3. 攻击路径验证：选取 ≥5 条可行/需条件路径，逐条写：前置条件 → 步骤 →
   预期结果 → 真实接口/命令（可复现）→ 波及范围 → 缓解缺失点。
4. 鉴权与身份专项：认证仅停留在哪一层（请求头？token？IP 绑定？），
   逐层列出可被伪装的理由与证据；CSRF/SRF/重放/幂等矩阵各一行。
5. 数据完整性专项：审计日志可伪造性（明文？HMAC？序号？）、状态文件篡改
   影响面、磁盘元数据（meta.json）对抗——逐项给证据与影响。
6. 修复验证：对选定的每条攻击路径给修复方案 + 验证方法（怎么证明修好了）。

【输出格式】A8-01..A8-NN；攻击树图（文本化）；攻击路径验证表；自反性攻击（两轮）。
```
